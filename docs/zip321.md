# ZIP 321 notes

[ZIP 321](https://zips.z.cash/zip-0321) defines the `zcash:` payment request URI
that Zcash wallets can construct payments from. BLINK implements it deliberately
and correctly.

## What BLINK uses ZIP 321 for

A BLINK payment request *is* a ZIP 321 URI. The QR code a recipient shares
encodes that URI, so a compatible wallet scanning it receives the actual payment
request — amount, recipient, memo — rather than a link to a web page.

## URI shape

```
zcash:<address>?amount=<decimal>&memo=<base64url>&label=<text>&message=<text>
```

- `amount` is a decimal ZEC value. BLINK validates it, caps it at 8 decimal
  places (1 zatoshi), and rejects anything larger than the ZEC supply.
- `memo` is the raw memo bytes, **base64url** encoded as ZIP 321 requires, capped
  at 512 bytes. BLINK rejects a memo attached to a transparent-only recipient,
  which cannot carry one.
- `label` and `message` are optional and used where appropriate.
- Query values use ZIP 321's per-character escaping rules (`encodeQchar`).

## Validation rules BLINK enforces

- The scheme is `zcash:`.
- The recipient is a valid transparent, Sapling or Unified Address. **Sprout is
  rejected.**
- The address network matches the deployment network. A mainnet address on
  testnet is rejected, and vice versa.
- An invalid or missing required parameter is rejected; it is never silently
  defaulted.
- Amounts are never silently changed, and the recipient is never silently
  replaced.
- Memos are validated for length and for whether the recipient can receive one.

## Two implementations, one authority

- `packages/payment-request` (TypeScript) — fast structural validation used by
  the web client and early request checks.
- `crates/blink-zcash` (Rust) — wraps the official `zip321` crate and is the
  authoritative check. When `BLINK_ZCASH_SERVICE_URL` is configured, the API
  requires an authoritative answer before accepting or returning a URI.

The TypeScript tests and the Rust tests both cover round-tripping and rejection
cases so the two stay aligned.

## What BLINK does not do

- It does not define its own URI scheme.
- It does not make a QR code merely point at a web page and call it a payment
  request.
- It does not implement its own cryptography or transaction construction; those
  belong to wallets and the Zcash protocol.
